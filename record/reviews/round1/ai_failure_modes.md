# Round 1 review — AI-agent failure modes (reviewer: AI-failure-modes agent, 2026-10-30)
Scope: DESIGN.md v0 against PROMPT.md process rules. Verdict: design is scientifically careful, but most of its
honesty guarantees are *stated* ("preregistered", "flagged", "reported as is") rather than *enforced*. Over 22 h with
many agents and context resets, unenforced rules decay. Changes below are cheap and within scope.

## A. Safeguards (enforce, don't promise)
1. **Machine-checkable preregistration.** Before any Part A/B result exists, write `config/prereg.yaml` with every
   threshold (τ=0.3, site-merge Jaccard 0.3, 80 % non-gap, pLDDT 70, length 0.7–1.3×, rescue ≥2/6, posterior 0.9,
   gain/loss costs 2/1, permutation p<0.01, p<1e-3+BH, s_null95, Tanimoto 0.5, pChEMBL 6, ≥3 species, ≥80 % clade),
   the M1–M4/F_anc/F_conv definitions, case-ranking score and co-folding readouts/decision rules. Commit it; record
   its sha256 in RESEARCH_TREE.md. Every pipeline run writes the hash of the config it used into its output
   manifest; `scripts/check_prereg.py` fails if config ≠ prereg unless a matching entry exists in DESIGN §12
   (deviation, reason, timestamp, *before/after* results both kept). Parameters "to be chosen on the benchmark" (τ,
   MSA method) are fixed by a committed script + benchmark split *before* Part A runs.
2. **Every stage writes a run manifest** (`results/<stage>/<run_id>/manifest.json`: snapshot id, config hash, git
   commit, seeds, runtime, input count, output count, dropped count *by reason*). No bare `except: pass` / silent
   defaults: fallbacks (TimeTree→rank proxy, FAMSA→MAFFT, PAE download failure, DIAMOND no-hit, ID-gap unmapped,
   missing MSA cache) must increment a named counter and set a per-row flag. `tests/test_no_silent_fallback.py` greps
   src/ for `except Exception:` / `except:` without logging + re-raise or counter.
3. **"No number without a producer."** Every number in REPORT.md/case pages is written as a key into
   `results/numbers.json` (generated by scripts, with source file + snapshot id). `scripts/check_report_numbers.py`
   extracts all numerals from REPORT.md and fails on any not traceable to numbers.json (allowlist for dates, years,
   citations). Same for figures: each PNG has a sidecar with generating script + input hashes.
4. **No hardcoded data or hand-typed cases.** Cases in `cases/<id>/case.yaml` are emitted by the candidate pipeline.
   Manual inputs (chosen ligand, cited paper, decoy) go in `cases/<id>/manual.yaml` with fields `author_agent`,
   `source` (DOI/PMID/PDB/ChEMBL id), `retrieved_at`. Lint: no accession/ligand literals in src/ outside tests.
5. **Citation & ID verification.** Every DOI/PMID/PDB/ChEMBL/UniProt id cited is resolved by a script (Crossref/
   PubMed/RCSB/UniProt API) and the title + a stored quote/snippet supporting the claim is cached in
   `cases/<id>/evidence/`. Unresolvable ids → evidence filter fails, not "pending". (LLM-fabricated citations are the
   most likely silent failure in filter 2.)
6. **Independent verifier agent with a fixed checklist** (`docs/VERIFY_CHECKLIST.md`), fresh context, given only
   committed artifacts (code, manifests, outputs) — never the producer's summary. Checklist: rerun stage on a small
   slice and compare hashes; check drop counts; check config hash = prereg; spot-check 10 random rows by hand;
   confirm controls ran and passed. Producer may not mark its own tree node [x]/[!]; only the verifier can.
7. **Toy data with known answers, run in CI (`pytest -m toy`) before real data:** planted gains/losses with recall
   0.7 (exists in §8.3); planted *no-event* trees (expected 0 events); planted fragments/low-pLDDT (expected U);
   synthetic pair sets with known H/N mix for F_anc; and **a no-convergence toy for the Δ test** (see B3).
8. **Whole-funnel null control (false-discovery rate of "convincing").** Run the full Part B candidate+filter
   pipeline on (a) species labels permuted within tier, (b) pseudo-clades of equal size drawn at random, (c) AFDB
   fragment pairs of the same protein. Report how many "convincing" gains/losses/changes the null produces vs real.
   If null yields comparable counts, cases are not reportable as events. Cheap: same code, different input.
9. **Funnel table is mandatory.** For each event type report: SOGs tested → candidates → passed artifact controls →
   filter 1 → 2 → 3 → co-folded → confirmed, plus the null-funnel counts (#8). Cases are never shown without their
   denominator.
10. **Positive-control gates.** Co-folding results for cases are not interpreted until the family's holo-PDB
    positive control reproduces (ligand RMSD threshold set in prereg) and the decoy/site-ablation controls behave;
    the BURROW recall on LIGYSIS and the SOG benchmark recall are reported before Part A numbers. Failed gate →
    result labelled "uninterpretable", not dropped.
11. **Snapshot stamping against subset leakage.** All outputs, app pages and REPORT sections carry the snapshot id;
    `check_report_numbers.py` fails if numbers.json mixes snapshots. Every Part A number is reported with the
    bias re-weighting (§4.2) side by side, and REPORT states "development subset, preliminary" in each section.
12. **Reproducibility check before REPORT:** a fresh agent runs `scripts/run_all.sh --snapshot <id> --slice toy`
    (and one real orthogroup slice) from a clean checkout and diffs outputs vs committed ones.
13. **Context-loss guard.** Each agent brief references prereg.yaml + the checklist; each agent ends with a
    RESEARCH_TREE-ready summary listing files produced and open doubts. "Not done / failed" is an allowed and
    expected status; REPORT must list planned items not completed (no silent scope shrinkage near the deadline).

## B. Places that invite p-hacking / cherry-picking, and fixes
1. **τ and the many thresholds** (§3.2, §3.3, §5). Fix: split the §8.1 benchmark orthogroups by hash(orthogroup id)
   into tune/test; choose τ and MSA method on tune by a committed objective (e.g. max F1), report test. Exclude tune
   orthogroups from being counted as *validation* of cases (filter 2 uses the same UniProt/BioLiP annotations →
   circularity). Report a sensitivity grid (τ ∈ {0.2,0.3,0.5}, pLDDT ∈ {60,70,80}, costs 2/1 vs 1/1) for headline
   metrics in full, never only the best cell.
2. **Curated cases / deep dives chosen post hoc** (§5, §6). Fix: candidates ranked by a preregistered score
   (e.g. posterior × persistence count × informative fraction). Deep dives = top-k by score per event type **plus
   one randomly sampled passing case** (seed from list) as an audit. Literature-famous examples (e.g. M-CSA
   convergent pairs) are positive controls, reported as "rediscovered", not as discoveries. Any manual override of
   the ranking is logged with reason in §12.
3. **Directional convergence Δ test (§4.2) is biased by selection.** Pairs are selected *because* s(b_derived,a) is
   significant, so Δ = s(b_derived,a) − s(b_sister,a) > 0 by regression to the mean even without convergence. Fix:
   select pairs using one derived member, compute Δ on *other* derived-clade members (held-out); and calibrate on
   the same procedure applied to H1 ortholog pairs / no-convergence toy (expected Δ≈0).
4. **Specificity-change permutation across tips (§5.2)** is anti-conservative (tips are phylogenetically
   non-independent) and run over thousands of SOGs. Fix: permute at clade level / phylogenetically constrained
   null, BH-correct across all SOGs tested, report number tested.
5. **"Convincing = filter 1 + one of 2/3"** lets weak evidence (e.g. ChEMBL activity "for the protein", not the
   site; JS conservation, which most pockets have) pass. Fix: prereg which evidence types count *for this event*
   (a loss needs experimental binding in the ancestral/outgroup state; site-level evidence ≥ protein-level), report
   each case's evidence tier explicitly; headline only all-three cases.
6. **Asymmetric rescue (§3.3)**: rescue is stated for loss A calls; gains also rest on A calls in sister lineages.
   Apply rescue to every A used by any candidate.
7. **F_conv,func = F_conv × PPV**: PPV from the annotated (biased, well-studied) subset. Report uncorrected F_conv,
   PPV and its CI separately; do not headline only the corrected number.
8. **Co-folding readouts** (ipTM, pLDDT, centroid distance) are many; pick one primary readout + threshold in
   prereg; derived/ancestral labels hidden (file names hashed) from the agent scoring the models.
9. **Iteration after seeing results** ("keep going until out of ideas", PROMPT). Every new method variant gets a
   tree node and is evaluated on the same held-out benchmark split; REPORT lists all variants tried, not just best.
