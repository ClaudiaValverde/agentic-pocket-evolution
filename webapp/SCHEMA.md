# Web app input schemas (schema versions `sogs-web-v1`, `case-v1`)

The web app only reads files. The pipeline writes them in the layouts below, and the app picks them up on the
next request (no restart, no import step). The toy fixtures in `webapp/fixtures/` follow these schemas exactly
and are generated by `webapp/fixtures/make_fixtures.py`. Their names start with `TOY` and the pages mark them as toy data.

Sharding convention used everywhere: `bucket = f"{zlib.crc32(key.encode()) & 0xff:02x}"` → file `bucket=<bb>.parquet`,
rows sorted by key. Small datasets may write all rows into the shards they hash to (the toy fixture has 1–3 shards).

## 1. Protein index (written by `scripts/webapp_build_index.py`; documented here for completeness)
`results/webapp_index/<snapshot>/tier{1,2}/bucket=<bb>.parquet` (in repo, ~29 MB) and
`/tmp/pe_big/webapp_index/<snapshot>/tier3/bucket=<bb>.parquet` (regenerable, ~460 MB for 23 M structures), key = `accession`.

| column | type | meaning |
|---|---|---|
| accession | string | UniProt accession as in the atlas |
| fragment, tier, unit_id, model_version | int16, int8, int32, int8 | atlas structure keys; pocket rows are in `ATLAS/pockets/tier<T>/<unit_id:06d>.parquet` |
| taxid, organism, n_res, plddt_mean, n_pockets_kept, status | | from `ATLAS/structures/…` |
| blob_kind | string | `tar_cif_gz` (AFDB v6 tar member, gzip mmCIF) or `foldcomp` (Foldcomp entry) |
| blob_file | string | tar file name under the AFDB v6 dir, or Foldcomp DB name under `ATLAS/foldcomp/` |
| blob_offset, blob_size | int64 | byte range of the member data / Foldcomp entry |

## 2. Orthogroup view: `results/sogs/<snapshot>/<orthology_version>/web/` (schema `sogs-web-v1`)
Change 2026-10-30 (SOG pipeline, `scripts/build_sogs.py --stage export`): the pipeline writes one directory per
orthology version (O1, O2, ...) under `results/sogs/<snapshot>/<orthology_version>/web/`; point the app at it with
`SOG_DIRS=results/sogs/<snapshot>/O1/web` (the default `results/sogs/<snapshot>` still works if a version is copied
or symlinked there). Extra columns beyond the ones below are allowed and are written (listed after each table);
`manifest.json` additionally carries `prereg_sha256`, `git_commit`, `seed`, `orthology_dir`.
```
results/sogs/<snapshot>/
  manifest.json                 {"schema": "sogs-web-v1", "snapshot", "orthology": "O2", "tau", "created_utc",
                                 "code_sha256", "toy": false}
  species_tree.nwk              rooted Newick guide tree; leaf labels = NCBI taxid (integers); internal labels optional
                                (clade names, e.g. "Mammalia"); branch lengths optional (ignored: cladogram)
  species.parquet               taxid int32, name string, code string (UniProt mnemonic, optional), clade string (optional)
  orthogroups.parquet           one row per OG (the list/search page)
  sogs.parquet                  one row per SOG
  sog_states/bucket=<bb>.parquet  one row per SOG x member (or SOG x species for G), sharded by og_id
```
**orthogroups.parquet**

| column | type | meaning |
|---|---|---|
| og_id | string | root OG id (Ancestra HOG id), unique |
| label | string | short human label (e.g. representative gene names) |
| n_species, n_members, n_sogs | int32 | counts |
| ref_accession | string | reference member (protein view link; nullable) |
| flags | string | `;`-separated flags (e.g. `orthology-uncertain`, `low-identity-msa`); empty if none |

Extra (pipeline): `level` (root HOG TaxRange), `half` (`tune`/`test`, prereg tune_test), `identity` (float32,
mean pairwise identity of the MSA). Flags written: `tune`/`test`, `control-family`, `low-identity-msa`, `no_models`.

**sogs.parquet**

| column | type | meaning |
|---|---|---|
| og_id, sog_id | string | `sog_id` = `<og_id>:g<k>`, unique |
| label | string | short label (e.g. `ATP site`) |
| footprint_columns | list<int32> | MSA columns of the footprint (§3.2) |
| footprint_ref | string | footprint in `ref_accession` UniProt numbering, `accession:pos pos …` (nullable) |
| n_P, n_W, n_A, n_U, n_G | int32 | member counts per state |
| event | string | `none` / `gain` / `loss` / `specificity` / `convergence` |
| event_node | string | tree node of the inferred event (internal label or `taxid,taxid` LCA spec; nullable) |
| score | float64 | preregistered ranking score S (nullable) |
| case_id | string | case linked to this SOG (nullable) |

Extra (pipeline): `n_sites`, `n_species_sites` (species with a member site in the Leiden community),
`footprint_size`, `n_insertion_cols` (footprint columns where < 50 % of members have a residue), `n_A_s70`, `n_U_s70`
(counts under the pLDDT >= 70 secondary stratum).

**sog_states/bucket=<bb>.parquet** (bucket of `og_id`)

| column | type | meaning |
|---|---|---|
| og_id, sog_id | string | keys |
| taxid | int32 | species (must be a leaf of `species_tree.nwk`) |
| accession | string | member protein (null for G) |
| state | string | one of `P` present, `W` weak-present, `A` absent-observed, `U` uninformative, `G` gene absent (DESIGN.md §3.3) |
| site_id | string | matched site (`<accession>:s<k>`, nullable) |
| pocket_id | string | representative atlas pocket of that site (nullable) |
| jaccard | float32 | footprint overlap of the matched site (nullable) |
| footprint_plddt | float32 | mean pLDDT of the footprint residues in this member (nullable) |
| reason | string | short reason for U/A/W (e.g. `plddt<90`, `rescue:2/6`, `terminal-truncation`); empty if none |

Extra (pipeline): `state_s70` (state under the pLDDT >= 70 secondary stratum), `fail_bits` (int16 bitmask of all
failed A criteria, `src/pocketevo/states.py:FAIL_BITS`), `in_sog` (the matched site is a Leiden member of the SOG),
`aligned_frac`, `len_ratio`, `n_filtered_pockets` (atlas-filtered pockets of the model, n_pockets_all − kept).
Reasons written: `no_model`, `model_sequence_mismatch`, `model_status`, `partial_site_overlap`, `aligned<0.8`,
`terminal_truncation`, `length_ratio`, `plddt<90`, `frac_lt70>0.2`, `sp_tm_overlap`, and for A rows whose model has
atlas-filtered pockets that were not yet re-described `rescue:pending` (A is provisional until rescue).

Several members per species (paralogs) are allowed; the matrix cell shows the strongest state
(P > W > A > U > G) and the count, the tooltip lists every member. Species of the tree without any row are drawn as
"no row" (blank), which is different from G.

State colours (fixed, also used in figures): P `#1b7837`, W `#a6dba0`, A `#d73027`, U `#bdbdbd`, G `#ffffff` with
grey outline.

## 3. Case view: `cases/<case_id>/` (schema `case-v1`)
```
cases/<case_id>/
  case.yaml          the record below (required)
  figures/           png/svg/pdf referenced by case.yaml
  cofold/            mmCIF/PDB models referenced by case.yaml (large models stay gitignored; see .gitignore)
  evidence/          cached API records/quotes (json/txt) referenced by case.yaml
```
`case_id`: `[A-Za-z0-9_.-]+`. Paths inside `case.yaml` are relative to the case directory and may not leave it.

```yaml
schema: case-v1
case_id: TOY_gain_01
title: "Toy gain of a pocket"
category: gain            # gain | loss | specificity | convergence | control
track: discovery          # discovery | annotation-first
label: supported          # convincing | supported | rejected | pending
toy: false                # true only for fixtures
summary: "One-paragraph plain-language summary."
og_id: TOYOG1             # links to the orthogroup view (optional)
sog_id: "TOYOG1:g0"
score: 12.5               # preregistered S (optional)
proteins:                 # members discussed in the case
  - {accession: P24941, taxid: 9606, species: Homo sapiens, role: derived,   # derived | ancestral | sister | outgroup | control
     state: P, site_id: "P24941:s0", pocket_id: "AF-P24941-F1-model_v6:m0", residues: "A:10 A:18"}
filters:                  # DESIGN.md §5.5; status: pass | fail | pending | na
  - {name: persistence,   status: pass, detail: "P in 5 species of clade X"}
  - {name: experimental,  status: pending, detail: ""}
  - {name: computational, status: pass, detail: "co-folding ligand pLDDT 85 vs decoy 60"}
artifact_checks:          # DESIGN.md §5.4; same status vocabulary
  - {name: footprint_plddt, status: pass, detail: "min 91"}
evidence:                 # every identifier verified against its API
  - {type: pdb, id: 1HCK, about_change: true, detail: "ATP bound at the site", file: evidence/1HCK.json}
  # type: pdb | uniprot | chembl | doi | pmid | mcsa | biolip | other
cofold:
  - {model_id: m1, accession: P24941, ligand: ATP, seed: 1, role: derived, file: cofold/m1.cif,
     metrics: {ligand_plddt: 85.0, min_pae: 1.2, centroid_dist_A: 1.5, posebusters_pass: true}}
figures:
  - {file: figures/tree.svg, caption: "SOG states on the species tree"}
literature:
  - {doi: "10.1038/xxxx", title: "…", note: "…"}
notes: "free text"
```
Required keys: `schema`, `case_id`, `title`, `category`, `label`. Everything else is optional; missing lists render
as "none recorded". Unknown keys are shown in a raw-YAML block, so nothing is hidden.

## 4. Changes made by web app phase 2 (2026-10-30)
Nothing the pipeline writes had to change. Additions that the app understands and that producers may use (all optional):
- **Versions.** The app lists every existing `results/sogs/<snapshot>/<v>/web/` for `v` in `PE_WEBAPP_SOG_VERSIONS`
  (default `O1_r2,O2_r1`; first existing = default selection) plus the TOY fixture. A new version appears on the next request.
- **`sog_states` extra columns read** (when present): `state_s70`, `model_accession`, `model_tier`. `model_tier` 1-3 means
  the member is in the atlas (link to the protein view with its pocket selected); tier 4 or null: shown without a link.
  The app reads only `og_id, sog_id, taxid, accession, state, site_id, pocket_id, jaccard, footprint_plddt, reason,
  state_s70, model_accession, model_tier`, and for one OG only the rows of the SOG columns on screen.
- **Case `evidence[].filter`** (string, optional): the `name` of the filter in `filters` that this evidence supports. A
  filter may instead list `evidence: [<id>, ...]`. The case page shows the linked evidence in each filter row.
- **Case `cofold[].file`** may be repo-relative under `results/` or `cases/` (e.g. `results/cofold/<run>/model.cif`) when the
  model is too large to copy into the case dir. Only files declared in `case.yaml` are served. `.cif`, `.mmcif`, `.cif.gz` are
  accepted. `cofold[].role` should be `ancestral` or `derived`: they fill the left and right viewer; `control`/`decoy`
  models are selectable in either. Pocket residues for the orange highlight come from `proteins[].residues`
  (`A:10 A:18`) of the same accession and role.
